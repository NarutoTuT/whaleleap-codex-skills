# Accessibility & Performance Checklist

## Scope and Evidence

- [ ] Exact environment, pages, states and timestamp recorded
- [ ] Audit mode and target standard/budget recorded
- [ ] Desktop/mobile and market/data conditions recorded
- [ ] Automated, manual, field, lab, code and inferred evidence separated
- [ ] Theme, app, content, Admin and platform ownership separated

## Accessibility

- [ ] Structure, language, landmarks and headings checked
- [ ] Names, roles, values and dynamic announcements checked
- [ ] Keyboard order, traps, focus visibility/restoration/obstruction checked
- [ ] Menus, dialogs, drawers, tabs, filters, carousels and forms checked
- [ ] Product media, variants, cart feedback and errors checked
- [ ] Contrast, non-text contrast and color independence checked
- [ ] Zoom, reflow, text spacing, orientation and target size checked
- [ ] Reduced motion and animation-dependent visibility checked
- [ ] Actual assistive technology coverage named

## Performance

- [ ] Field and lab data interpreted separately
- [ ] LCP element and delay phases identified
- [ ] Slow INP interaction and main-thread work identified
- [ ] CLS sources and shifting elements identified
- [ ] Images, fonts, CSS and network waterfall checked
- [ ] JavaScript, listeners, DOM and long tasks checked
- [ ] Apps, embeds, pixels and third-party value/cost checked
- [ ] Performance budgets and regression conditions defined

## Reporting

- [ ] Every P0/P1 has evidence, impact, owner and acceptance test
- [ ] Root-cause hypotheses include confidence
- [ ] Implementation belongs to the correct Skill or human owner
- [ ] Untested and blocked scope is explicit
- [ ] Gate does not overstate conformance or production performance
